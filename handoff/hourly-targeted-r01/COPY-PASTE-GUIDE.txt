THE CHANGE

Keep the current detector, hourly pipeline, shared writer lease, ingestion,
raw revision tables, current-file pointers and reporting architecture.

- Added/modified files, including older cycles: FILES with exact relative paths.
- Deletions and renames: ALL; reconcile current paths before reporting.
- Missing/invalid metadata baseline or unusable ingestion index: ALL.
- Existing manual/request rebuild route: ALL.
- Global FORCE_REHASH or FORCE_REBUILD_REPORTING_FACTS: ALL when invoked through
  that route. The hourly UNCHANGED gate still skips the notebook.
- FORCE_REHASH_PATHS remains the changed set even in ALL. An ETag-only change
  cannot disappear behind a matching modification-time/length shortcut.
- ALL discovery lists metadata for the entire tree; it does not automatically
  decode unchanged workbooks. FILES gives Spark only exact selected file paths.

No pipeline parameter redesign is needed. Retain:
  FM_RUN_MODE (String): HOURLY
  FM_METADATA_JSON (String/expression):
    @activity('Check_Demand_Metadata').output.output
  Notebook in the True branch of Refresh_only_when_changed; False branch empty.
  The condition must use the parsed detector NeedsRefresh Boolean.

The worker recomputes the delta against metadata-success.json under worker.lock.
This is cheap Python metadata comparison and avoids trusting a detector result
that may predate another completed writer. It does not read workbook contents.

WHY THE TWO SUCCESS MARKERS ARE DIFFERENT

The existing reporting signature records that report tables were committed.
It does not prove the model refresh succeeded. model-success.json, in the
existing ForecastMasterRefreshState store, records the report signature plus
workspace/model/report-prefix identity only AFTER confirmed model completion.

A model failure or unconfirmed completion leaves that marker behind; retry
still refreshes the model even if reporting itself returns unchanged. A marker
write failure also fails the run. An already-confirmed signature skips the
model even during an otherwise repeated reconciliation. First deployment has
no marker and the reporting signature calculation changes, so allow one
conservative model synchronization; later unchanged runs skip it.

A SAME_CONTENT receipt may update LastSuccessAtUtc. Excluding its derived
PathFirstSeenAtUtc from the signature avoids report/helper rewrites and model
refreshes for metadata-only touches with unchanged bytes and rules.

metadata-success.json advances only after source, catalog, reporting, confirmed
model state, snapshot validation, and all prerequisite receipt writes succeed.
It is now the last success write. A retry can reuse completed content revisions
without duplicating them. The original shared lease and failure receipts remain.

Case                             Expected evidence
No changes                       NeedsRefresh false; notebook not started.
One addition / old-cycle edit    RefreshMode FILES; "Files inspected" equals
                                 selected count, not historical inventory count.
ETag-only edit                   Exact file content checked. If bytes unchanged,
                                 no report rewrite/model refresh after marker sync.
Removed file                    RefreshMode ALL even with ChangedFiles=[];
                                 old current path/facts gone; raw revision retained.
Rename                          ALL; old current path retired, new path active;
                                 identical raw bytes reuse the retained revision.
Changed months or dimensions    Affected source slice replaced; old keys absent;
                                 unaffected files and cycles unchanged.
Failed workbook / catalog       Run fails; no model refresh; baseline retained.
Failed/unconfirmed model        Baseline retained; next run retries model despite
                                 already-committed reporting signature.
Receipt write failure           Baseline retained; no falsely successful pointer.
Invalid/missing baseline        Detector requests rebuild; worker uses ALL.
Manual fact rebuild             ALL and reporting early return bypassed.

For the affected source compare before/after current fact key counts and sums
against its saved workbook. Check uniqueness of:
  SourceRevisionID, Channel, SubChannel, Sector, Month, ComponentKey
Verify the old revision's raw observation count is unchanged. Test removed rows,
nulls and numeric zero separately. Do not validate only total row counts.

Capacity verification: compare matched before/after runs using the same changed
file and capacity conditions. Record metadata listing, Spark session startup,
"Discover matching files", "Read saved workbook", projection and model durations,
plus CU(s) in Fabric Capacity Metrics. FILES removes the recursive Spark root
listing; it does not eliminate Spark startup, the metadata detector's full
listing, Delta metadata work, or a required model refresh. No measured CU saving
or runtime percentage is claimed from local tests.

The existing nonempty-inventory and nonempty-projection guards remain. If all
bridges disappear, listing is incomplete, or a workbook has no configured fact
components, the run fails and retains the last successful baseline rather than
silently presenting a successful empty rebuild. Resolve the source condition
before retrying. An unrelated file changed after the detector snapshot is picked
up by the next metadata comparison; FILES is not a full-tree atomic snapshot.
